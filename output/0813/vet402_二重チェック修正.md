## 各所見の対応

### 中-1【非単調バグ】scoreEconomicActivity 買い手側 — 修正
`src/lib/scoring/helpers.ts`。`l1.purchaseCount>0` で無条件に L1 採用しx402破棄していたのを、**両アクティブ信号の Math.max** に変更（売り手 payee-engine と対称）。強x402(95)＋初L1(75) が 95→75 に落ちて ALLOW→WARN 反転し得た穴を封鎖。TDD: 「強x402に初L1が付いても x402水準を下回らない＝正の証拠は単調非減少」テストを追加（既存は弱x402＋強L1しか見ていなかった盲点）。docstringも「DOMINATES」→「stronger of the two」に正確化。

### 中-2A【Sybil穴】getObservedDeliveryStats の distinctBuyers — 修正（実装）
`src/lib/db/observed-purchases.ts`。生wallet数だった `distinctBuyers` を、買い手側 `countDistinctFunders` と同型の **funder-collapse**（`countDistinctBuyerFunders`）に変更。売り手が同一funderの複数walletで受領多様性ボーナスを水増しできた穴を封鎖。funder未知は自分自身のsourceとして数える permissive degrade、funder索引欠落時は生カウントへフォールバック（correctness gateにしない）。`scoreL1Receiving` の「funder-collapsed by the reader」docstringが実態と一致。pg TDD で「同一funderの2買い手は1に畳まれ、deliveryCountは3のまま」「索引空なら生カウント」を検証。

### 中-3A【中立性・ToS整合】global blacklist 解除経路 — 修正（実装）
`recordOperatorOverride(action:"blacklist_removed")` を書く経路が皆無だった穴を実装。
- `src/lib/db/customer-lists.ts`: `removeGlobalBlacklistEntry({wallet, reason})` を追加。operator-wide(apiKeyId NULL)のblacklist行を削除し、**実際に削除された時のみ** 理由付き `blacklist_removed` を公開ログへ追記（削除0件なら記録なし＝透明性ログに幻の撤回を残さない）。追加時と同じく await。
- `src/app/api/admin/global-lists/route.ts`: `DELETE` ハンドラを追加。POST/DELETE共通の `adminGate`（本番configトラップ＋レート制限＋admin bearer）へリファクタ。撤回も理由必須(min1)。
- TDD: pg で「解除が公開ログに理由付きで載る／未blacklist walletは無記録・customer-scoped行は不可侵」、route で「bearerなし403・誤bearer403・空理由400・不正wallet400・POST認証回帰」。

### 中-2B【憲法・誤標示】agentバッジのdegraded非対称 — 修正
`src/lib/badge/trust-badge.ts` に score→badge の橋渡し `agentBadgeState` / `payeeBadgeState` を新設（`hasUnavailableInput` で degraded を導出。engineをimportせず構造型で受けDB非依存を維持）。両バッジルートをこの橋へ委譲。agentは `signals.sybil.flags`、payeeは明示`degraded`＋`signals.flags`（形状差のためsubject別導出、payeeはflags経由もbelt-and-suspenders）。degradedなagentが赤Flagged→**琥珀Caution**へ、payeeと対称化。
- **route配線テスト**を追加（`resolveBadgeState` の純関数テストは degraded を既算入力で受けるため配線漏れを捕捉できない、という指摘に対応）: degraded-BLOCK→caution・genuine-BLOCK→flagged・agent/payee対称・null→caution を橋関数で固定。加えて実ルート `GET` を注入DBで駆動し unsigned→Unverified を検証（chain不要な分岐で実ハンドラを通す。degradedの実ルート端到端はRPC必須のため橋テストで固定）。

### 軽-1B【route-type掃除の完遂】— 修正
`payeeMessage`/`agentPassportMessage` を新規 `src/lib/verify-message.ts` へ集約。payees/verify・agents/verify の非handler export を撤去、passport route のクロスimportを lib参照へ張替え、テスト2本のimportも張替え。正典一本化。`next build` EXIT0を維持。

### 軽-2B・docstring・最適化
- **軽-2B（修正・コメント）**: `packages/middleware/src/core.ts` `isScoreStale` の docstring に2点を明文化 — (1)鮮度フィールド皆無bodyは maxScoreAgeMs によらず常にfresh扱い（鮮度ゲート不適用）、(2)`maxScoreAgeMs=+Infinity` は scoredAt年齢チェックを無効化するが `cacheExpiresAt` の上限とパース不能scoredAtのstale判定は残る。※testに影響なし（コメントのみ、middleware dist は test の再build で追随）。
- **docstring（修正）**: `helpers.ts` の L1「same shape as x402」を実態へ正確化 — deliveryは**trusted observatory writerが書込時に担保**（read時導出不可）／独立性・dustは**x402に類似だが同一SQLではない**read時フィルタ、と分離明記。
- **最適化（見送り・明記）**: L1 reader のDB往復削減は見送り。
  - `getObservedDeliveryStats`: 集約1＋funder-collapse1の計2往復。単一クエリ化は funder_wallets 欠落時に deliveryCount/uniqueDays まで巻き添えでthrowし、現行の「funder索引が無くても件数は取れ、生カウントへ退避」という degrade 挙動を変えてしまうため不可（挙動保存が条件）。
  - `getObservedPurchaseStats`: funder-collapse は行を*落とす*必要があり（purchaseCount/uniqueDays/distinctCounterparties が生存行から導出）、単純なSQL集約に置換すると funder-collapse と permissive-degrade の意味論が変わる中リスク。かつ本番は現在0行で1往復。「低リスクのみ」の範囲外のため見送り。
